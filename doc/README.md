# doc/

全部文档。四个子目录各管一件事，互不重叠。

| 目录 | 管什么 | 命名 |
|---|---|---|
| `doc/` | **项目级规范 + 架构决策记录（ADR）** | 规范：`中文标题.md`；ADR：`YYMMDDHHmmV1_决策_标题.md` |
| `plan/` | **开发计划 / 方案** | `YYMMDDHHmmV1_中文标题.md` |
| `log/` | **开发日志**，一天一篇 | `YYMMDDHHmmV1_开发日志.md` |
| `todo/` | **已确认、暂缓做的事项** | `YYMMDDHHmm_主题.md` |

## 四者的区别（最容易混）

- **plan** 回答「做什么、按什么顺序、怎么算完成」——是**承诺**。
- **log** 回答「今天实际做了什么、卡在哪」——是**记录**。
- **todo** 回答「确认要做、但现在不做的有哪些」——是**待办池**。
- **doc** 回答「以后都要怎么做」「当初为什么这样决定」——是**规则与历史**。

```
plan  →  打算做什么
代码   →  实际怎么做
log   →  今天做到哪了
todo  →  欠着什么
doc   →  规则是什么、为什么这样设计
```

## 命名规则

- **时间戳**：`YYMMDDHHmm`，取文档**创建**时间（北京时间），之后不改。例：`2601261430` = 2026-01-26 14:30。
- **版本号**：`V1` 起步。只有**重写**时升版本（结构变了、结论翻案、范围扩大），旧版保留不删；小修改直接改原文件。
- **标题用中文**，下划线连接时间戳版本与标题。
- `doc/doc/` 下的规范文件**不带时间戳**（如 `提交规范.md`），因为它们长期有效、被频繁引用；修改记录写在文件头。

## 状态写在文件头，不移动文件

计划完成、废弃都**不移动文件**（移动会让代码注释和其他文档里的引用失效），在文件头标状态：

```markdown
# 订单导出功能方案
日期：2601151330
状态：📝 设计中 / 🚧 开发中 / ✅ 已完成 / ⏸️ 暂停 / ❌ 废弃
```

完成时补一节「实施结果与偏差」；废弃时写一句为什么、被哪份文档取代。

## README 是唯一事实来源

- 每个目录的 `README.md` 描述该目录的规范；跨目录的规范只放 `doc/doc/`，不在多处重复。
- **规范与代码冲突时以规范为准**，改代码；规范过时就更新规范，重大变化写一条 ADR。
- 不手工维护「文档索引」列表，`ls` 就是索引——手工列表一定会过期。

## 所有文档通用

- 不写密钥、真实 key、口令、用户数据。账号信息只写「存放在哪」，不写值。
- 引用代码写相对路径，引用其他文档写文件名全称。
