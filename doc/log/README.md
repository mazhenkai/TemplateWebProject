# doc/log/

开发日志。**一天一篇**，当天开工时创建。

命名：`YYMMDDHHmmV1_开发日志.md`，如 `2601261058V1_开发日志.md`。时间戳取创建时间，之后不改。一篇实在写不下才开 V2。

> 注意区分：`doc/log/` 是**人**写的开发日志；根目录 `log/` 是**程序**写的运行日志。

## 写法

不写流水账。按事情分节，每节回答这几件事：

```markdown
# 260126 开发日志

## 功能 / 问题标题（状态：✅ 完成 / 🚧 进行中）

### 做了什么
- 改动要点与关键文件
- 对应计划：`doc/plan/2601151330V1_xxx.md`

### 遇到的问题
- 现象 → 根因 → 处理方式（临时 / 根治）

### 验证
- 跑了什么命令、结果如何（如「集成测试 23 条全绿」）

### 提交
- `abc1234` feat: 实现 xxx
- `def5678` fix: 修复 xxx

## 明天的打算
- ...
```

## 硬性约束

1. **只记已经发生的事**。打算做的进 `plan/` 或「明天的打算」，暂缓的进 `todo/`。
2. **问题写清现象和处理**。只写"遇到 bug"没有价值。
3. **附 commit hash**，日志和 git 历史能互相对上。
4. **发布到生产要记**：发布内容、执行的命令、手动执行的 `ALTER`、回滚方式。
5. **当天写，不事后补**。补写会丢掉"当时为什么这么想"。
6. 不记录密钥、真实 key、用户数据。
