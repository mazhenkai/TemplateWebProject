# 推送与协作规范

> 更新时间：2026-11-26

提交规范管「怎么提交」，本文档管「谁能推送、AI 助手能做什么」。

## 1. 铁律：push 只能由负责人本人执行

**任何 AI 助手、子代理、自动化脚本都不得执行 `git push`。** 助手只做到 `git commit`，需要推送时把命令写出来交给负责人。

理由按重要性排序：

1. **推送不可逆**。本地 commit 错了可以改；push 出去被拉取、被 fork、被流水线记录，就收不回来。
2. **推送需要凭据，助手不应持有**。凭据进入助手上下文，就可能出现在对话记录和日志里。
3. **并行操作会互相覆盖**。助手改本地历史的同时负责人在推送，两边一撞就是分叉。

## 2. 操作权限

| 操作 | 助手 | 说明 |
|---|---|---|
| `git status` / `log` / `diff` | ✅ | 只读 |
| `git add` / `commit` | ✅ | 日常工作 |
| `git branch` / `checkout -b` | ✅ | 新建分支安全 |
| `git reset --soft <未推送的提交>` | ⚠️ | 仅限拆分本地未推送的 commit，先说明再做 |
| `git reset --hard` | ❌ | 会丢工作区修改 |
| `git push` | ❌ | 负责人专属 |
| `git push --force` | ❌ | 任何人任何情况都不行 |
| `rebase` / `filter-repo` 已推送的提交 | ❌ | 改写公共历史 |
| 跑 `deploy.sh` / `push.sh` / `daily_pipeline.sh` | ❌ | 会推送或改生产 |
| 跑 `check.sh` / `pack.sh` / 测试 / `verify/` | ✅ | 不改远端 |

## 3. 拆分 commit 的安全流程

```
1. 查边界：git rev-list --count origin/main..HEAD
   结果为 0：没有未推送的 commit，不要动历史
2. 确认要重切的范围全部未推送；混有已推送的，立即停止并告知负责人
3. git reset --soft origin/main
4. git reset                      # 取消暂存，保留工作区
5. 按依赖顺序逐个 add + commit，每步都验证能编译 / 能跑
6. 把 push 命令交给负责人
```

动历史之前确认没有人正在推送；最好的确认方式是**不在可能有人推送的时候动历史**。

## 4. 多远程

- 远程名固定（如 `github`、`gitee`），由 `opt/*/push.sh` 统一推送，未配置的跳过。
- 推送密钥放 `~/.ssh/` 或 `opt/**/keys/`（已 gitignore），不进仓库。
- 推送前 `push.sh` 依次执行：工作区干净检查 → `check.sh` → 测试 → 推送。
