# 建表规范

> 更新时间：2026-11-26
> 适用：PostgreSQL。其他数据库按同样思路调整。

## 1. Schema 规划

| Schema | 用途 |
|---|---|
| `prd` | 生产环境，只放正式数据 |
| `dev` | 开发 / 测试环境，随便写 |
| `public` | 默认 schema，不使用 |

测试数据与生产数据**靠环境（schema）隔离，不靠表名区分**。

## 2. 表名前缀

| 前缀 | 用途 | 示例 |
|---|---|---|
| `tb_` | 正式业务表 | `tb_user`、`tb_order` |
| `opt_` | 运维管理表 | `opt_log`、`opt_config` |
| `dev_` | 开发调试表 | `dev_seed` |
| `tmp_` | 临时表，用完即删 | `tmp_import` |

> ⛔ **禁止 `test_` 前缀**，禁止在同一 schema 内建影子表做测试。测试数据放 `dev` schema 的正式表里。

| 环境 | Schema | 允许的前缀 |
|---|---|---|
| 生产 | `prd` | `tb_`、`opt_` |
| 开发 | `dev` | `tb_`、`opt_`、`dev_`、`tmp_` |

## 3. 必备字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `BIGSERIAL PRIMARY KEY` | 主键（对外暴露的 ID 可另设业务主键，如 `ord_xxx`） |
| `created_at` | `TIMESTAMPTZ NOT NULL DEFAULT NOW()` | 创建时间 |
| `updated_at` | `TIMESTAMPTZ NOT NULL DEFAULT NOW()` | 更新时间 |
| `deleted_at` | `TIMESTAMPTZ` | 软删除（可选） |

## 4. 命名

- 表名、字段名：小写 + 下划线，表名用单数（`tb_order` 而非 `tb_orders`）。
- 普通索引：`idx_<表名>_<字段>`；唯一索引：`uniq_<表名>_<字段>`。
- 外键字段：`<被引用表去前缀>_id`，如 `order_id`。
- 时间一律 `TIMESTAMPTZ`，不用 `TIMESTAMP`。
- 每张表、每个非显然字段写 `COMMENT`。

## 5. 从 dev 迁移到 prd

- **只迁移 `tb_`（和需要的 `opt_`）表**，其余留在 dev。
- 用**显式白名单**同步，不用前缀匹配：白名单是 `config/app.env` 的 `TB_WHITELIST`，新增正式表时必须同时修改，防止调试表误入生产。
- 同步脚本：`bash opt/linux/sync_tables.sh`（默认只读对比两边结构）/ `sync_tables.sh apply`（补建 prd 缺少的表，仅负责人执行）。
  ```sql
  CREATE TABLE IF NOT EXISTS prd.tb_order (LIKE dev.tb_order INCLUDING ALL);
  ```
- `IF NOT EXISTS` 只补建不存在的表，**不同步已有表的字段变更**。加字段需手动在 prd 执行同一条 `ALTER`，再跑一次 `sync_tables.sh` 核对两边结构一致。
- 所有变更 SQL 写进 `backend/migrations/`，见该目录 README。

## 6. 数据同步方向

| 方向 | 状态 |
|---|---|
| prd → dev | ✅ 允许，用于把生产数据拉到开发调试 |
| dev → prd | ❌ 禁止，开发数据严禁进入生产库 |

## 7. 建表前检查

- [ ] 前缀正确，没有 `test_`
- [ ] 有 `id` / `created_at` / `updated_at`
- [ ] 索引命名符合规范
- [ ] 迁移 SQL 已放入 `backend/migrations/`
- [ ] 正式表已加入部署白名单
- [ ] 方案文档里写了表结构
