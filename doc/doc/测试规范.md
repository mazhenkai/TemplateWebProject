# 测试规范

> 更新时间：2026-11-26

## 1. 核心原则

**测试数据与生产数据靠环境隔离，不靠表名或参数区分。**

- dev 环境（dev 端口 / `dev` schema）：日常开发与测试，随便写。
- prd 环境（prd 端口 / `prd` schema）：只放生产数据，不在上面跑测试。

不要用 `?mode=test` 参数、请求头、`test_` 影子表在同一环境里切换数据源——这类机制冗余且有串到生产的风险。

## 2. 测试分层

| 层 | 位置 | 依赖 | 何时跑 |
|---|---|---|---|
| 单元测试 | 跟随源码或 `tests/unit/` | 无外部服务 | 每次提交前 |
| 集成测试 | `tests/integration/` | dev 后端 + dev 数据库 | 提交前、每日流水线 |
| 端到端 | `tests/e2e/` | dev 前后端 | 发布前 |
| 通路验证 | `verify/` | 外部服务 | 环境变化时手动 |

## 3. 集成测试规则

1. **地址从配置读，只能指向 dev**；检测到 prd 端口或 `prd` schema 直接失败退出。
2. **自动产生的数据统一打标记**（如标签 `test-auto`、名称前缀），清理只按标记删。
3. **自清理**：

   | 时机 | 动作 |
   |---|---|
   | 开始前 | 确认后端可用；清理历史残留的标记数据；补齐测试账号 |
   | 结束后 | 删除本次产生的标记数据（无论成败） |

   因此集成测试**可以独立、重复执行**，不依赖外部准备脚本，跑完不留残留。
4. **测试账号**由测试启动逻辑自动确保存在，不靠手工执行 SQL。账号口令放 `config/app.env`。

## 4. 测试控制台 / 调试页

- 仅在开发构建可用；**生产构建访问返回 404，且不显示入口**。
- 所有请求直接打 dev 后端。

## 5. 写测试的习惯

- 修 bug 先写一个能复现它的测试，再修。
- 代码与对应测试同一个 commit。
- 测试名说清场景和期望：`TestUpload_RejectsFileOver10MB`。
- 不为凑覆盖率写断言为空的测试。

## 6. 流水线

每日流水线**无条件跑测试**；工作区不干净时只跳过推送和打包，不跳过测试。测试失败不推送。
