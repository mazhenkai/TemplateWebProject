# doc/doc/

**项目级规范的唯一存放处**，以及架构决策记录（ADR）。凡是「以后都要这么做」的约定放这里，不散落到各目录 README。

## 现有规范

| 文件 | 管什么 |
|---|---|
| `项目阅读说明.md` | 接手项目的阅读顺序、调用链、修改前检查 |
| `开发环境说明.md` | 机器、解释器、端口、配置位置、常用命令（**唯一允许写本机具体信息的文档**） |
| `提交规范.md` | commit 格式、type、拆分 |
| `推送与协作规范.md` | 谁能 push、AI 助手能做什么 |
| `建表规范.md` | schema、表前缀、字段、索引、迁移 |
| `测试规范.md` | 测试分层、测试数据与清理 |
| `部署规范.md` | dev → prd 发布流程、禁止操作、检查清单 |

规范文件名不带时间戳；修改时在文件头更新「更新时间」和一句变更说明。

## ADR（架构决策记录）

做了一个**难以反悔**的决定、且当时的备选方案值得留下时写一条。命名：`YYMMDDHHmmV1_决策_标题.md`，如 `2601191900V1_决策_缓存选用Redis.md`。

格式三段，不写成八股：

```markdown
# 决策：<一句话>
日期：2601191900
状态：已采纳 / 已推翻（被 xxx 取代） / 待定

## 背景
当时面对什么问题，有哪些约束。

## 备选方案
A / B / C 各自的关键利弊，一句话一个。

## 决定与理由
选了哪个，为什么。**最重要的一条**：如果将来要推翻，需要付出什么代价。
```

推翻一条 ADR 时不删原文，改状态并新写一条。
