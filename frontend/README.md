# frontend/

前端应用本体。技术栈不限（Next.js、Vite、Vue 等），按框架惯例组织子目录。复制模板后把「目录职责」改成实际内容。

## 目录职责（示例，按实际改）

| 路径 | 职责 |
|---|---|
| `src/app/` 或 `src/pages/` | 页面路由 |
| `src/components/` | 组件 |
| `src/lib/` | 工具库、接口请求封装 |
| `src/store/` | 状态管理 |
| `src/types/` | 类型定义 |
| `public/` | 静态资源 |

## 硬性约束

1. **接口请求统一走 `src/lib/` 下的一个封装**，不在组件里直接 `fetch` 拼地址。
2. **后端地址从配置读**，不写死域名或端口。配置来源与前缀规则见 [`config/README.md`](../config/README.md)。
3. **带 `NEXT_PUBLIC_` / `VITE_` 前缀的变量会公开到浏览器**，只能放公开信息。
4. **调试页、测试控制台只在开发构建可用**，生产构建必须返回 404 且不出现入口。
5. 代理、npm 源等配置写进框架配置文件或 `.npmrc`，不散落在脚本里。
6. 提交前跑 lint 与类型检查（命令写在 `doc/doc/开发环境说明.md`）。

## 路由规划

在根 `README.md` 或本文件维护一份路由清单，新增页面时同步更新：

```

```
