# backend/migrations/

数据库表结构变更 SQL。命名、前缀、字段规则见 [`doc/doc/建表规范.md`](../../doc/doc/建表规范.md)。

## 命名

```
NNN_说明.sql
```

三位编号递增，如 `001_auth.sql`、`002_orders.sql`、`003_order_add_status.sql`。编号一旦提交不再修改，也不复用。

## 硬性约束

1. **只追加，不修改已执行的迁移**。要改表结构就新写一个编号更大的文件。
2. **先在 `dev` 执行并验证，再到 `prd` 执行**。
3. **SQL 不写死 schema**，用 `search_path` 或执行脚本传入 schema，保证同一份文件能在 dev / prd 执行。
4. **新增正式表（`tb_`）时同步修改部署脚本的白名单**，否则不会同步到 prd。
5. **加字段、改字段不会被自动同步**，需在 prd 手动执行同一条 `ALTER`，并在当天开发日志里记录。
6. 能写成可重复执行的就写成可重复执行（`IF NOT EXISTS`）。
