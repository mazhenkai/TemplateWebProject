# tests/

单元测试与集成测试。测试数据与环境规则见 [`doc/doc/测试规范.md`](../doc/doc/测试规范.md)。

## 与 verify/ 的区别

| 目录 | 回答什么 | 何时跑 |
|---|---|---|
| `tests/` | 代码行为对不对 | 每次提交前、每日流水线 |
| `verify/` | 外部通路通不通（数据库、第三方 API） | 环境变化时手动跑一次 |

## 建议结构

```
tests/
├── unit/          不依赖外部服务，秒级完成
├── integration/   打 dev 后端 / dev 数据库
└── e2e/           端到端（按需）
```

语言惯例要求测试和源码放一起的（如 Go 的 `_test.go`），单元测试跟随源码，本目录只放集成与端到端测试。

## 硬性约束

1. **集成测试只打 dev**，地址从配置读；发现指向 prd 直接报错退出。
2. **测试自清理**：开始前清理历史残留，结束后删除本次产生的数据，无论成败。可以独立、重复执行。
3. **测试数据打统一标记**（如标签 `test-auto`），清理只按标记删，不按"看起来像测试"删。
4. **代码与对应测试同一个 commit 提交**，不提交跑不过的测试。
5. 修 bug 先补一个能复现它的测试。
