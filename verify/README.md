# verify/

一次性验证脚本：确认外部通路是否可用（数据库连通、第三方 API 调得通、域名证书有效等）。

## 与相邻目录的区别

| 目录 | 回答什么 |
|---|---|
| `verify/`（本目录） | **通不通**：跑一次出结论，不需要服务在跑 |
| `tests/` | **对不对**：代码行为是否符合预期 |
| `opt/` | **日常反复做的运维动作**：启动、重启、部署 |

## 命名

`verify_<对象>.<ext>`，如 `verify_db.py`、`verify_oss.sh`、`verify_llm_api.py`。

## 硬性约束

1. **配置从 `config/app.env` 读**，支持命令行参数覆盖。
2. **输出明确结论**：成功 / 失败，失败时给出原因分类（网络不通、鉴权失败、配置缺失、超时），不静默失败。
3. **只读**：验证脚本不写数据库、不改远端状态。确需写入的，写完立即清理并在脚本头注释说明。
4. **不打印密钥**，输出里出现的凭据一律脱敏。
