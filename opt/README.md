# opt/

运维脚本：日常反复执行的动作。按平台分 `linux/`、`windows/`，**同一个动作在两边同名**（`dev_daily.sh` / `dev_daily.ps1`），便于记忆。

项目内其他位置不放启动脚本。

## 标准脚本清单

按需实现，不需要的不建。名字尽量保持一致，换项目不用重新记。

「模板」列为 ✅ 的已在 `linux/`、`windows/` 提供通用实现（`sync_tables` 只有 Linux 版），复制后只需填 `config/app.env`；其余按项目编写。

| 脚本 | 作用 | 会改远端 / 生产？ | 谁能跑 | 模板 |
|---|---|---|---|---|
| `env.sh` | 公共变量：项目根、加载 `app.env`，被其他脚本 `source` | — | — | ✅ |
| `dev_daily.sh` | 开发环境 `start/stop/restart/status/log`，开工时按天归档日志 | 否 | 任何人 / AI | ✅ |
| `check.sh` | 提交 / 推送前检查：敏感文件被跟踪、密钥、本机路径 / IP | 否 | 任何人 / AI | ✅ |
| `pack.sh` | `git archive` 打包**已提交**文件到 `dist/`，保留最近 N 个 | 否 | 任何人 / AI | ✅ |
| `rerun_prd.sh` | 重启生产环境 | **是** | 负责人 | |
| `sync_tables.sh` | 白名单表结构 dev → prd：`diff` 只读对比，`apply` 补建缺表 | `apply` 改 prd | `diff` 任何人 / AI；`apply` 负责人 | ✅ |
| `deploy.sh` | 构建 → `sync_tables.sh apply -y` → 重启生产 | **是** | 负责人 | |
| `push.sh` | 工作区干净 → check → 测试 → 推送各远程 | **是** | 负责人 | ✅ |
| `daily_pipeline.sh` | 每日：check → 测试 → 有新 commit 则推送 → 打包 | **是** | 负责人 | ✅ |
| `prd_to_dev.sh` | 生产数据同步到开发（单向） | 写 dev | 负责人 | |

## 硬性约束

1. **会推送、会改生产的脚本只由负责人执行**，AI 助手不执行。
2. **脚本开头 `set -euo pipefail`**，失败立即退出并打印失败在哪一步。
3. **配置从 `config/app.env` 读**，路径、端口不写死在脚本里（`env.sh` 统一加载）。
4. **数据同步只有 `prd → dev` 方向**，不写任何 `dev → prd` 的数据同步脚本。表结构走 `deploy.sh` 白名单。
5. **密钥不进仓库**：推送用的私钥放 `opt/**/keys/`（已 gitignore）或 `~/.ssh/`。
6. **工作区不干净时**：测试照跑，跳过推送和打包。
7. 用法、参数写在脚本头部注释；新增脚本同步更新本表。

## 放在项目外运行的脚本

如果脚本实际运行在项目外（如服务器上一个统一的 `deploy.sh` 管多个项目），在本目录放一份**留档副本**，并提供同步脚本刷新副本，避免副本与真实运行版本不一致。
